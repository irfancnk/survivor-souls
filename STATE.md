## DECISIONS
- Design language: Archero / Archero 2 (menus, loop, chests, daily/weekly quests, gear merge, talents, energy). Look: Dark Souls, realistic, not dismal. User decision 2026-10-11.
- Naming map: energy=Estus, gold=Souls, gems=Ember Shards, chests=Reliquaries, daily=Oaths, weekly=Pilgrimage, chapter=Realm, room=Chamber. See GAME_PLAN sec 2.
- Art source (KAN-27): local TRELLIS.2 for static props/environment; Meshy paid for rigged characters, enemies, bosses, held weapons. Meshy.ai -> FBX -> Unity URP. Paid Meshy plan for ship assets (free = CC BY, needs credit). Tri budget: hero 5-8k, enemy 1.5-3k, boss 8-12k, prop <1.5k.
- Test Mode (KAN-144): every unlock system reads `TestMode.IsOn` (one flag, `settings.testMode`); never write fake progress for it. Hero roster KAN-100, gear KAN-139, Grand Reliquaries KAN-137 wire themselves to it. 2026-10-15.
- Heroes (KAN-153, first slice of KAN-100): `HeroRoster` + `HeroDefinition` assets in `Data/Heroes/`; a hero profile is one permanent `PlayerStats` source (horde baseline counts it). Knight = free reference hero; Shadow Ranger = 1,000 Ember Shards. Test Mode: every hero free, no charge, no ownership written. Percent sources add up: soul tree Vigor 5 (+25 %) cancels the Ranger -25 % max health. 2026-10-16.
- Versioning (KAN-142): `VERSION.json` is the one version source; `Tools/bump-version.sh` is its only writer. Every merge to main bumps (PATCH fix / polish / follow-up / tooling, MINOR new feature, MAJOR user decides), build +1 always, `CHANGELOG.md` entry, git tag `vX.Y.Z+N` on the merge commit, closing Jira comment says "Shipped in X.Y.Z (build N)". The build stamp writes PlayerSettings at build time only. Started at 0.2.0 (build 1). 2026-10-15.
- Gate arrow (KAN-63): on the screen edge, never on the ground under the Knight. Render choice (a): Blender model baked to one sprite (cheapest, 1 UI element), not a screen-space mesh. Dim while the portal is locked, bright when open; hidden in the boss fight until the arena portal opens. 2026-10-16.
- Level-up re-roll (KAN-67): 2 per run, not per level-up; not on the chest upgrade screen; a re-roll keeps the tier odds and counts for pity. 2026-10-15.
- Meta upgrades (soul tree KAN-98, later gear / heroes) are permanent `PlayerStats` sources and stay out of the KAN-92 horde power scaling: the horde scales only with in-run skills. 2026-10-15.
- Boss damage (KAN-163): boss hits are a share of the Knight's max health, cap 0.5, phase 2 x1.15; 3 clean hits of a boss's biggest attack kill a fresh Knight; every damaging attack warns >= 0.6 s; contact damage flat and below a telegraphed hit. Armor (KAN-139) will subtract after the share. 2026-10-16.
- Crossbow hold: two hands, crossbow on Spine2 + arm IK baked in Blender script. Recoil procedural in Unity (no extra clip). 2026-10-12 (KAN-11).
- Sounds: procedural (SfxBuilder). No paid packs (Irem rule). 2026-10-12.
- Grass: geometry blades per tile (opaque, no alpha test: cheap on mobile TBDR). 2026-10-12. Not used in Realm 1 since KAN-25 (GrassBuilder, Grass.shader, GrassPusher kept for later realms).
- Realm 1 = snowy seaside shore, bright low-noise floor so the dark Knight reads (KAN-25, 2026-10-13). Terrain = custom mesh + world-space shader, not Unity Terrain.
- Orientation: portrait only, iOS + Android. User decision 2026-10-12.
- Render pipeline: URP. Reason: mobile perf, good look.
- Git LFS: NOT on. git-lfs not installed. Add later before big binary assets.
- Repo: public, github.com/irfancnk/survivor-souls.

- Menu UI: UI Toolkit, not uGUI. Reason: one UXML/USS per screen, easy for AI to edit, cheap on mobile.
- Scenes built by editor script. Reason: reproducible, diffable.
- Placeholder art = procedural (no Meshy access yet). One palette material for characters/props. Reason: few draw calls, swap later.
- Game lighting: realtime unshadowed point lights + trilight ambient, no bake. Reason: simple, fast on mid phones. Bake later if needed.
- Gameplay camera: Archero style, fixed yaw 0, pitch 55.
- Font: Unity default for now. No font download.
- Tracking: Jira site survivorsouls.atlassian.net, project SurvivorSouls (key KAN). One ticket per user task. In-dev status name = "In Development".
- Docs: Confluence space SS = source of truth for design docs. Repo Docs/ keeps copy. New doc goes to right numbered folder; old doc to 99 Archive (no delete).

## KNOWN ISSUES
- Mac build needs `-buildTarget OSXUniversal` on Unity command line. Else URP SSAO/post shaders stripped, PC pipeline fails.
- Unity build rewrites Assets/Settings/*RPAsset + GraphicsSettings (prefilter fields). Do not commit that noise.
- Since KAN-157 a Game / MainMenu scene rebuild leaves generated controllers, tile prefabs, scenes and roster materials unchanged. If `git status` shows them after a rebuild, the builder output really changed (see `[StableAssetWriter] Changed:` in the log).
- `Mathf.SmoothStep` is an interpolator, not GLSL smoothstep. Use `TextureFactory.SmoothStep`.
- Batch Unity in a worktree killed a lingering IL post-process runner of the open editor once. Harmless, editor respawns it.
- Archer is placeholder quality (primitive look). Replace with Meshy model.
- Agent cannot screenshot Mac screen: `screencapture` has no Screen Recording permission. Use dev build + `-ss-screenshot` instead.
